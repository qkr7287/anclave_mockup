Anclave — 구현 가이드 (대화형 · 단계별 프롬프트)

1차 자동(/goal) 구현이 휑함·편차로 폐기된 뒤, Claude와 대화형으로 화면을 화면마다 크롬 렌더로 확인하며 만드는 방식으로 전환했다. 각 STEP에는 ① 구현 프롬프트와 ② 검증·QA 프롬프트가 짝으로 있다 — 만들기만 하고 끝내지 않고, 매 STEP을 검수해 품질·정렬·금지사항을 잡는다(1차 실패의 핵심 교정). 사양 자체는 Anclave-구현계획(§8 DoD)·Anclave-디자인스펙(Q1~Q29·가드레일)·Anclave-시스템정리가 들고, 이 문서는 실행 순서와 복붙 프롬프트만 담는다.

0이 방식(대화형)이란 · 왜 /goal 대신

이 가이드의 프롬프트는 Claude에게 보내는 일반 메시지다(/goal 명령 아님). 각 STEP은 ① 구현 프롬프트로 만들고 → Claude가 npm run dev(5177)로 렌더 확인·보고 → ② 검증·QA 프롬프트로 금지사항·밀도·이상을 잡고 → 사용자 확인 → 커밋 → 다음 STEP.

1준비 · 복붙 방법

  • 브랜치: feat/mockup-impl에서 작업. 1차 폐기본은 archive/v1-sparse-impl에 박제(반면교사).
  • 디자인 원본: 디자인스펙(Q1~Q29)이 1차 사양. 픽셀·뉘앙스가 애매하면 for_claude/design-workshop/qN-*.html 원본 참조(Q1~Q24의 출처). 단 폰트는 14px floor 상향 적용(원본 11~13px는 참고값).
  • 서버: app/에서 npm run dev → 5177. STEP 동안 띄워두고 Claude가 크롬으로 렌더 확인.
  • STEP 진행: ① 구현 프롬프트 복붙 → Claude 구현·보고 → ② 검증·QA 프롬프트 복붙 → 발견된 문제 수정 → 사용자 OK → 커밋 → 다음 STEP.
  • 커밋: STEP 끝마다 즉시. 예 feat(impl): G1 자원맵 3계층(4.2~4.4). 1차엔 커밋이 없어 되돌릴 체크포인트가 없었다 — 반드시 STEP마다.
  • 한 STEP이 크면(예: G13 5화면) 둘로 쪼개도 된다. 작을수록 밀도가 산다.
★ 퀄리티 끌어올리기 기법 — 전 STEP 공통(매 화면에 적용 · 자원맵·차트 등 비주얼 화면일수록 필수):
  • ① HyperCube 컴포넌트 포팅 — 처음부터 짜지 말고, 같은 도메인의 검증된 컴포넌트(HyperCube/frontend/src/lib/components/host-board/ ResourceMap·GpuPanel·VramBar·SliceCell)를 React로 번역해 Anclave 토큰·14px만 입힌다. 품질·속도 둘 다 보장.
  • ② 라이브러리부터 검증 — 헥사 라이브러리(honeycomb-grid 등) 설치 후 자명한 벌집을 먼저 렌더해 tessellation이 진짜 되는지 확인하고 본격 구현. 토대 먼저 못 박기.
  • ③ 비교 루프 2~3회 — 한 방에 끝내지 말고, 스크린샷을 레퍼런스 이미지와 나란히 놓고 "뭐가 다른지" 차이를 적어 고치기를 2~3 라운드. (덤: 컴포넌트는 샌드박스 라우트에서 단독 완성 후 조립하면 iterate가 쉽다.)

2공통 규칙 · 절대 금지 체크리스트

★ 밀도 게이트(이진) — 1차 실패 지점. 모든 화면 above-fold(스크롤 전)에 정보영역 ≥4 · 단일 테이블/단일 차트만 있는 화면 금지(요약 KPI행·필터·보조 패널 동반) · KPI 카드는 [지표 24~32px + 델타/스파크/게이지 중 1개+], 높이 96~120px, 숫자만 덩그러니 금지.
★★ "꽉 참"이 진짜 기준 (영역 개수로 속이지 말 것). 영역 ≥4는 최소선이지 상한이 아니다 — 큰 빈 카드 4개로 면적만 채우는 것도 휑함(금지·미충족). 목표는 잘 만든 GPU 호스팅/SaaS 콘솔 대시보드처럼 above-fold가 빈틈없이 꽉 차는 것(보통 KPI행 3~4 + 메인 테이블/차트 + 보조 패널 2~3개가 한 화면에). 1차는 이 밀도의 약 1/4이라 폐기됐다 — 같은 실수 반복 금지.
★ 밀도 실측 레퍼런스 — for_claude/desigin/예시페이지.png (이 페이지만큼 꽉 차야 함). 모든 STEP의 ①구현·②검증 공통 벤치마크 — 만들기 전·검증 때 이 이미지를 열어 대조한다. 단 화면마다 콘텐츠는 다르니 레이아웃 복사가 아니라 "같은 밀도·완성도 수준"을 그 화면 고유 콘텐츠로 달성하는 게 목표(게시판이 GPU 카드처럼 되면 안 됨). 핵심 패턴:
  • 패널 안에 미니카드 그리드: 큰 카드 4개가 아니라 한 패널에 컴팩트 카드 6개+(각 카드 = 이름 + 타입/상태 배지 + 작업률·메모리 2지표+막대 + 슬라이스/온도/사용자).
  • KPI 타일: 값만 X — 게이지/아이콘 + 보조수치(적정·한도) 동반(예: 60% + p95 58%).
  • 세그먼트 바(VRAM = 작은 셀 ~30개) · 슬라이스 7분할 = 7개 카드 행(사용자·모델·컨테이너·작업률·VRAM 압축).
  • 이벤트 테이블(상태 닷 + 메시지 + 조치 링크, 여러 행) · 상태 배지·색 곳곳에.
  • 2열 구성 + 각 열 패널 2~3개 적층 → above-fold가 화면 끝까지 빈틈없이.
⚠ 단, 이 레퍼런스의 "상단 가로 탭 nav"는 따라하지 말 것 — Anclave는 좌측 아코디언 사이드바·상단 GNB 없음(디자인스펙 Q2). 가져올 건 밀도·패널 구성이지 네비 패턴이 아니다.
구조를 더 보려면 소스 참고(읽기만): HyperCube/frontend/src/lib/components/host-board/(GpuCompareCards·GpuPanel·VramBar·SliceCell·ResourceMap) + routes/gpu-hosting/+page.svelte — Svelte·타 토큰·11px·상단nav는 미적용, 밀도 구조만 참고.
★ 모니터링 페이지 무스크롤 규칙 (4.2·4.3·4.4 자원맵 · 4.7 관제). 1920×1080 한 화면에 세로·가로 스크롤 없이 전부 들어오게 — 페이지 height:100vh 고정, 바깥 스크롤 0. 넘치는 콘텐츠(이벤트 로그·테이블 등)는 해당 패널 내부 스크롤(overflow:auto)로만 흡수 — 폰트 축소·페이지 스크롤 금지(14px floor·레이아웃 안정성 유지). 1920 무스크롤이 1순위, 1280/1024는 Q16 반응형 reflow 허용. ②검증 때 1920×1080에서 스크롤 0인지 꼭 확인.
★ 절대 금지 체크리스트 (의뢰인 지정 — ②검증 프롬프트가 매 STEP 이걸 항목별로 본다. 어기면 미충족)
  • 레이아웃 안정성: 한 번 정한 영역(카드·패널·차트)은 콘텐츠가 늘어도 크기 불변 — 넘치면 내부 스크롤(overflow:auto)/말줄임으로 흡수, 형제 영역 침범·잘림 금지(min-width:0).
  • 테이블 헤더: 제목 nowrap·크기 고정 — 축소·2줄 줄바꿈 금지. 컬럼이 안 맞으면 글씨 축소가 아니라 컬럼 숨김/가로 스크롤.
  • 글씨 줄여 욱여넣기 금지 · 텍스트 겹침 0 · 같은 행 카드 높이 정렬(높이 튐 0) · 정렬 어긋남 0.
  • AI 티 금지: 카드 좌측 accent bar · orb · aurora · 무의미 gradient · decorative SVG/배경 장식 · 장식 아이콘 금지(아이콘은 액션·상태 의미 있을 때만). 의심되면 빼기.
  • 휑함 금지: 빈 공간만 차지하는 카드 · 단일 테이블/차트 화면 금지(위 밀도 게이트).
  • ★ 컨테이너 꽉 채우기(차트·맵·콘텐츠) — 전 페이지 공통, 강제: 패널 안 차트/맵은 가로·세로 둘 다 패널을 꽉 채운다 — Recharts ResponsiveContainer width="100%" height="100%" + 부모 flex-1 min-h-0 min-w-0(무스크롤 100vh가 definite height 제공). 차트 좌우/상하에 큰 빈 공간 금지 — flex-1인데 차트가 작게 떠 있고 주변이 비면(예: 부하 추이 그래프) 미충족. 헥사 그리드도 패널을 가장자리까지 꽉. ★게이지(ArcGauge)도 컨테이너에 맞게 스케일(shrink-0 고정 소형으로 떠 있는 거 ❌, 카드/패널 공간 차면 키움). ★LineChart는 꺾은선(직선 세그먼트 · Recharts type="linear") — 부드러운 곡선(monotone/curved) 금지.
  • ★ 프로그레스 바(가로 채움 막대) 금지 — 전 프로젝트, 안 씀: 작업률·사용률·메모리·VRAM% 등을 ━━━ 95% 같은 가로 채움 막대로 표시하지 말 것 · 수치는 숫자(+게이지/스파크/카운트업)로 · (세그먼트 셀 viz[VRAM 32셀]·아크 게이지·꺾은선은 채움 막대 아님 = 허용) · 특히 자원맵 3계층(4.2 MIG 슬라이스 막대·4.3/4.4 작업률 막대 등) 다 제거.
★ 생동감(심심하지 않게) — "장식"이 아니라 "허용 수단"으로. AI 티 금지와 양립한다. 무미건조 금지 ≠ 장식 추가 — 위 금지 항목(orb·aurora·gradient)은 그대로 두고, 생동감은 아래로 낸다:
  • 밀도 + 데이터 viz: 자원맵 헥사곤(Q10)·아크 게이지·미니 라인차트(꺾은선)·히트맵·상태 배지·세그먼트 셀 — 화면이 정보로 꽉 차 살아 보이게(프로그레스 바는 안 씀).
  • 허용 모션(Q7 · 전부 prefers-reduced-motion 게이트): 진입 fadeUp·stagger(자식 .05/.16s)·핵심 지표 count-up(~900ms)·핵심 헤딩 shiny 텍스트·primary CTA 버튼 sweep·hover lift. 그 외 효과는 금지(§2 절대 금지).
  • 상태 색(ok/warn/danger)로 정보에 생기. 정확한 값은 디자인스펙 Q7·Q5·Q10·Q15.
"절제하되 죽이지 말 것" — 금지(장식)와 생동(밀도·viz·허용모션)을 헷갈리지 않기.

↓ ① 구현 프롬프트 끝에 붙는 공통 꼬리말:

[공통 꼬리말] — ① 구현용PageShell·공통 컴포넌트 재사용. 디자인스펙 픽셀·가드레일 준수(무미건조 금지 — Q7 허용 모션·데이터 viz·상태 색으로 생동감, 장식은 X). 각 화면 above-fold 정보영역 ≥4(단일 테이블/차트 금지), KPI 카드는 지표+델타/스파크/게이지 구성. §9.2 역할 접근·§9.3 상태 적용. ★구현 전·중에 밀도 벤치마크 for_claude/desigin/예시페이지.png(필요하면 HyperCube gpu-hosting 소스 구조)를 열어, 레이아웃 복사가 아니라 "같은 밀도·완성도 수준"을 이 화면 고유 콘텐츠로 목표 삼아. ★구현하면서 §2 "절대 금지 체크리스트"(레이아웃 안정성·테이블 헤더 nowrap·정렬·AI 티·휑함·★차트/맵·게이지 컨테이너 꽉·라인 꺾은선·프로그레스 바 금지)를 꼭 다시 보고 위반 0으로 맞춰. 다 만들면 npm run build 통과시키고 npm run dev로 크롬 1440/1280/1024 렌더를 직접 보며 고친 뒤, 결과 보여주고 멈춰(커밋은 ②검증 후).

↓ ② 검증·QA 프롬프트의 공통 골격(각 STEP 카드엔 화면이 채워진 버전이 있다):

5막힘 · 되돌리기

  • 밀도가 또 안 나오면 — 그 화면을 PageShell 슬롯에 다시 얹고, "above-fold 4영역 중 빈 곳에 무엇을 넣을지" 구체 지시(요약 KPI·랭킹·로그·분포).
  • ②검증에서 금지 위반이 반복되면 — 해당 항목만 콕 집어 재지시(예: "이 테이블 헤더가 2줄 줄바꿈됨 → nowrap·컬럼 숨김으로").
  • 한 STEP이 무거우면 — 화면 단위로 쪼개 다시 요청(작을수록 밀도가 산다).
  • 되돌리기 — STEP마다 커밋했으니 git reset --hard로 직전 STEP 복귀. 1차 폐기본: git checkout archive/v1-sparse-impl && cd app && npm run dev.
