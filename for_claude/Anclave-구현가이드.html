Anclave — 구현 가이드 (대화형 · 단계별 프롬프트)

1차 자동(/goal) 구현이 휑함·편차로 폐기된 뒤, Claude와 대화형으로 화면을 화면마다 크롬 렌더로 확인하며 만드는 방식으로 전환했다. 아래 STEP 0~14의 프롬프트를 위에서부터 하나씩 복붙하면 28화면 목업이 완성된다. 작업 사양 자체는 Anclave-구현계획(§8 DoD)·Anclave-디자인스펙(Q1~Q29·가드레일)·Anclave-시스템정리가 들고 있고, 이 문서는 실행 순서와 복붙 프롬프트만 담는다.

0이 방식(대화형)이란 · 왜 /goal 대신

이 가이드의 프롬프트는 Claude에게 보내는 일반 메시지다(/goal 명령 아님). Claude가 한 STEP을 구현하고 → npm run dev(5177)로 직접 크롬 렌더를 보며 밀도·정렬·AI 티를 잡고 → 결과를 보여주면, 사용자가 확인하고 다음 STEP으로 넘어간다.

1차 실패의 진짜 원인은 "/goal이 나빠서"가 아니라 큰 단위 + 주관적 DoD + 강제 템플릿 없음 + 사람 리뷰 없음 + 커밋 없음이었다. 앞 4개는 이미 고쳤고(작은 STEP·객관 DoD·PageShell·브랜치/커밋), 남은 사람 리뷰를 이 대화형 방식이 채운다. 품질이 결정되는 STEP 0(기반·템플릿)을 제대로 잡는 게 핵심 — 모든 화면이 여기서 상속한다.

1준비 · 복붙 방법

  • 브랜치: feat/mockup-impl에서 작업(확정 문서 + Goal1 baseline에서 분기). 1차 폐기본은 archive/v1-sparse-impl에 박제(반면교사).
  • 서버: app/에서 npm run dev → 5177. 같은 STEP 동안 띄워두고 Claude가 크롬으로 렌더 확인.
  • 복붙 순서: §3 STEP 0부터 하나씩. 각 STEP 
    박스를 통째 복사해 Claude에 보낸다. Claude가 구현·렌더 확인·결과 보고 → 사용자 OK → 커밋 → 다음 STEP.
  • 커밋: STEP 끝마다 즉시. 메시지 예 feat(impl): G1 자원맵 3계층(4.2~4.4). 1차엔 커밋을 안 해 되돌릴 체크포인트가 없었다 — 반드시 STEP마다 커밋.
  • 한 STEP이 크면(예: G13 5화면) 둘로 쪼개도 된다. 작을수록 밀도가 산다.

2매 프롬프트 공통 규칙 (STEP 프롬프트 끝 "공통 꼬리말"에 이미 녹아 있음)

★ 밀도 게이트(이진) — 1차 실패 지점. 모든 화면 above-fold(스크롤 전)에 정보영역 ≥4 · 단일 테이블/단일 차트만 있는 화면 금지(요약 KPI행·필터·보조 패널 동반) · KPI 카드는 [지표 24~32px + 델타/스파크/게이지 중 1개+], 높이 96~120px, 숫자만 덩그러니 금지.
  • 가드레일: AI 티 금지(카드 좌측 accent bar·orb·무의미 gradient·장식 SVG 없음) · 절제된 구분(배경 톤·구분선 우선) · 디자인스펙 픽셀값 정확.
  • 안정성: 텍스트 겹침 0 · 가로 스크롤은 표 내부만 · 같은 행 카드 높이 정렬 · 테이블 table-layout:fixed·헤더 nowrap.
  • 재사용: 새 화면은 PageShell(KPI행+섹션 슬롯)과 공통 컴포넌트/차트를 재사용 — 직접 레이아웃 새로 짜지 말 것(편차 차단).
  • 검증: npm run build exit 0 · 콘솔 0 · 크롬 1440/1280/1024 렌더 육안(겹침·휑함·정렬·높이 튐 0) · 다크/라이트 · 역할(§9.2)·상태(§9.3).

↓ STEP마다 붙는 공통 꼬리말(프롬프트에 포함됨):

공통 꼬리말PageShell·공통 컴포넌트 재사용. 디자인스펙 픽셀·가드레일(AI 티 금지) 준수. 각 화면 above-fold 정보영역 ≥4(단일 테이블/차트 금지), KPI 카드는 지표+델타/스파크/게이지 구성. §9.2 역할 접근·§9.3 상태 적용. 다 만들면 npm run build 통과시키고 npm run dev(5177)로 크롬에서 1440/1280/1024 렌더를 직접 보며 겹침·휑함·정렬·높이 튐을 0으로 고쳐. 그 다음 결과(스크린샷/요약) 보여주고 커밋 제안해.
