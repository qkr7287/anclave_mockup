Anclave — /goal 실행 가이드

설계·구현계획·DoD가 완비된 상태에서 Claude Code의 /goal로 28화면 목업을 단계별 자동 구현하기 위한 사용 설명서. 조건문은 그대로 복붙해서 쓴다.

0/goal이란

  • /goal <완료 조건> — Claude가 그 조건이 충족될 때까지 매 턴 자동으로 계속 작업한다.
  • 매 턴 끝에 빠른 모델(Haiku)이 "조건 충족?"을 판정 → 미충족이면 자동으로 다음 턴 시작.
  • 그래서 완료 조건이 객관적으로 검증 가능해야 한다(빌드 exit·파일 존재·렌더·스크린샷). 모호하면 오판해서 조기 종료하거나 끝나지 않는다.
/goal <조건>목표 설정(새 조건이면 기존 대체)
/goal현재 목표 상태 확인
/goal clear활성 목표 삭제
📏 조건문 최대 4,000자(공식). 하지만 조건문은 "완료 상태"라 보통 100~300자면 충분 — 우리 조건문도 230~290자라 여유. · 요구: Claude Code v2.1.139+, 신뢰 대화, Hooks 활성.

1좋은 조건 3원칙

  1. 측정 가능한 종료 상태 — 테스트 결과·빌드 exit·파일 개수·렌더 여부. (예: npm run build exit 0, "28라우트 렌더")
  2. 검증 방법 명시 — Claude가 어떻게 증명할지. (예: "1440/1280/1024 스크린샷에서 겹침 0")
  3. 바뀌면 안 되는 제약 — (예: "상단 가로 GNB 없음", "사양 = for_claude 4종 문서")
⚠️ 긴 작업 지시를 조건문에 넣지 말 것. 작업 내용(어떻게 만들지)은 구현계획 §8 DoD가 들고 있으니, 조건문은 "그 DoD를 충족" + 핵심 검증만 짧게 참조한다. 그래야 빠른 모델이 매 턴 깔끔히 판정한다.

2선행 메시지 + 3단계 조건문 (그대로 복붙)

순서: ① 선행 메시지(일반 입력) → ② /goal 조건문 → 충족 시 검증·커밋 → 다음 Goal. ①은 매 Goal 시작 전마다 붙인다.

① 선행 정독 메시지 — 매 /goal 전 1회 (일반 메시지로 먼저 입력)
💡 짧은 조건문만으론 문서를 대충 읽고 갈 수 있어서, 아래를 먼저 보내 문서를 정독·준수하게 한 뒤 /goal을 건다.
먼저 이걸 일반 메시지로 ↓ (Goal N의 N만 바꿔 매 Goal 재사용)이제 Goal N 구현 시작이야. 먼저 for_claude의 Anclave-구현계획·디자인스펙·시스템정리를 꼼꼼히 정독해. §8 Goal N의 작업 순서대로 진행하고 DoD를 모두 충족해. §9 검증 매트릭스와 디자인스펙 전 화면 공통 가드레일(AI 티 금지·여백/정렬/밀도)을 그대로 따르고, 화면·라우트·사이드바 메뉴는 IA 8 대분류 순서로. §5 canonical 시드 정본대로 더미를 써. npm run dev로 서버를 띄워 화면 만들 때마다 크롬(claude-in-chrome)으로 실제 렌더를 보면서 여백·정렬·밀도·AI 티·텍스트 겹침을 눈으로 확인·수정해(코드만 보고 끝내지 말 것). 폭별 스크린샷은 resize_window로 1440/1280/1024 뷰포트를 바꿔 캡처해. 그다음 이어서 거는 /goal 목표를 향해 구현해줘.
② /goal 조건문 — Goal 1 (기반 · 셋업·셸·라우터·공통컴포넌트·더미·28라우트 골격)
/goalapp 폴더에서 npm run build가 에러 없이 통과하고 구현계획 §8 Goal 1 DoD를 모두 충족한다. 사양 = for_claude/Anclave-시스템정리·구현계획·디자인스펙. 검증: build exit 0, src/{lib,data,components} 존재, App.tsx의 28개 라우트가 IA.xlsx 화면 IA 순서와 동일, src/data는 §5 canonical 정본+참조무결성 충족, 사이드바=IA 8대분류이며 상단 가로 GNB 없음, 콘솔 에러 0.
Goal 2 — P1 화면 (자원맵 3계층·대시보드·신청·승인·마켓·카탈로그)
/goalapp에서 npm run build 통과하고 구현계획 §8 Goal 2 DoD를 모두 충족한다. P1 8화면(4.2~4.5·4.8·4.10·4.12·4.17) 완성·더미 표시, 자원맵 3계층 헥사곤 동작, §9.2 접근·§9.3 상태·공통 DoD 적용. 디자인스펙 Q1~Q29와 가드레일(AI 티 금지·밀도·정렬) 준수. 검증: 1440×900·1280×800·1024×768 스크린샷에서 텍스트 겹침·휑함·정렬 어긋남·카드 높이 튐 0, 콘솔 에러 0.
Goal 3 — P2·P3 화면 (나머지 20화면)
/goalapp에서 npm run build 통과하고 구현계획 §8 Goal 3 DoD를 모두 충족한다. P2·P3 20화면 완성·더미 표시, 28화면 전부 라우트 렌더, 다크/라이트·빈상태·스켈레톤 적용. 디자인스펙·가드레일 준수, §9.3 상태 매트릭스 충족. 검증: 28라우트 모두 렌더, 1440/1280/1024 스크린샷 위배 0, 콘솔 에러 0.

3실행 흐름

1
Goal 1 조건 입력 — /goal + Goal 1 조건문. 그 턴부터 Claude가 DoD 충족을 향해 자동 작업.
2
자동 반복 + 크롬 실시간 확인 — 매 턴 끝에 Haiku가 판정 → 미충족이면 다음 턴 자동. Claude는 npm run dev 띄우고 화면마다 크롬(claude-in-chrome)으로 실제 렌더를 보며 여백·정렬·AI 티를 눈으로 잡아간다(코드만으로 끝내지 않음). (사람은 지켜보다 막히면 개입)
3
충족 → 자동 종료 → 검증 게이트 — 조건 충족 시 /goal이 멈춘다. 다음 Goal로 넘어가기 전 아래 게이트를 반드시 통과(특히 크롬 라이브 검증 — 빌드/DoD만으론 여백·정렬·AI 티를 못 잡는다).
✓ 검증 게이트 (매 Goal 완료 후 · 통과해야 다음 Goal)
  • ☐ npm run build exit 0 (TS·빌드 에러 0)
  • ☐ DoD 항목별 자체 검증(데이터·라우트·무결성 수치로 표 작성)
  • ☐ 크롬 라이브 검증: npm run dev 띄우고 dev 서버 주소(localhost:5xxx) navigate 1회 허용 → claude-in-chrome으로 해당 Goal 화면들 실제 렌더
  • ☐ 콘솔 에러 0(브라우저 콘솔 직접 확인)
  • ☐ 스크린샷 1440×900·1280×800·1024×768: resize_window로 뷰포트를 각 폭으로 바꾼 뒤 캡처(claude-in-chrome 캡처는 창 크기로 정규화되므로, 폭을 직접 바꿔야 폭별 정밀 검증이 됨) · 텍스트 겹침·휑함·정렬 어긋남·카드 높이 튐·AI 티 육안 0
  • ☐ 통과 → 커밋 → 다음 Goal
4
다음 Goal — 게이트 통과·커밋 후 /goal + 다음 조건문(새 조건이면 자동 대체, 또는 /goal clear 후 입력). Goal 3까지 반복.
✅ 단계를 나눈 이유: 한 번에 28화면을 자동 구현하면 중간 검증·되돌리기가 어렵다. 기반 → P1 → 나머지로 끊어 각 단계 끝에 사람이 확인·커밋하면 안전하고, 공통 컴포넌트 완성 후 화면당 작업이 가벼워진다.

4효율 팁 · 주의

효율

  • 선행 정독 메시지를 매번 먼저(§2 ①) — 짧은 조건문만으론 문서를 대충 읽고 갈 수 있다. "구현계획·디자인스펙·시스템정리 정독 + 가드레일 준수 + IA 순서"를 일반 메시지로 먼저 보낸 뒤 /goal을 걸면, 자세한 사항이 다 반영된다.
  • 크롬으로 실시간 보며 구현 — 여백·정렬·AI 티·밀도는 코드만으론 판정 못 한다. npm run dev 띄우고 화면마다 claude-in-chrome으로 실제 렌더를 직접 보며 수정하면 퀄리티가 크게 오른다. (전제: dev 서버 + claude-in-chrome 권한 · localhost는 한 번 허용 필요)
  • 조건문은 짧게, 작업 내용은 DoD 참조 — 빠른 모델 판정이 깔끔해진다.
  • 커밋 먼저 — /goal 시작 전 깨끗한 상태(체크포인트). 자동 반복이라 되돌릴 때 편하다. (현재 feat/design-docs 브랜치에 4종 문서 커밋됨)
  • 한 Goal = 한 /goal — 욕심내서 한 번에 28화면 걸지 말 것. 3단계 유지.
  • 막히면 중간에 일반 메시지로 힌트를 줘도 된다(/goal은 유지된 채 그 맥락 반영).

주의

  • turn 제한을 조건문에 넣지 말 것 — turn 수는 검증 가능한 DoD가 아니다. 30턴 넘게 안 끝나면 사람이 진행 보고 중단 판단.
  • 조기 종료 의심 시 — 충족됐다는데 결과가 부실하면, 조건을 더 구체화해서 다시 건다(예: 빠진 검증 추가).
  • 무한 반복 의심 시 — 조건이 영원히 충족 불가일 수 있다. /goal clear 후 조건 점검.
  • 빈 app/ 스캐폴딩이 있어도 무방 — Goal 1이 처음부터 재세팅한다.
